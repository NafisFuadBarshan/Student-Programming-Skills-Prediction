# Student Programming Skills Prediction

Predicting how many programming languages a student knows using **multivariate linear regression**, implemented two ways: from scratch with **NumPy** (normal equation) and with **scikit-learn**, plus a ridge variant and a mean baseline. Models are compared on accuracy, training time, and learned coefficients.

> Course project for **CSE 404: Artificial Intelligence & Expert Systems Lab**, Department of Computer Science & Engineering, University of Asia Pacific.

---

## Overview

| | |
|---|---|
| **Task** | Regression: estimate a student's number of programming languages known |
| **Target** | `How many programming languages do you know?` |
| **Features** | 23 survey questions, expanded to 47 numeric columns |
| **Dataset** | `Studentdata.csv` (256 student records) |
| **Models** | Manual NumPy OLS vs. `sklearn.linear_model.LinearRegression`, plus manual Ridge and a mean baseline |
| **Split** | 80% train / 20% test (`random_state=42`) |

## Results

Test-set metrics (80/20 split, `random_state=42`, 52 test rows) plus 5-fold cross-validated R² on all 256 rows:

| Model | MSE | RMSE | MAE | Test R² | CV R² (mean ± std) |
|---|---|---|---|---|---|
| Mean baseline | 1.0382 | 1.0189 | 0.7472 | -0.0103 | n/a |
| Scikit-learn OLS | 0.8939 | 0.9455 | 0.7027 | 0.1302 | 0.046 ± 0.086 |
| Manual OLS (NumPy) | 0.8939 | 0.9455 | 0.7027 | 0.1302 | 0.046 ± 0.086 |
| Manual Ridge (α=100) | 0.6522 | 0.8076 | 0.5952 | 0.3654 | 0.254 ± 0.065 |

- The manual and scikit-learn OLS models agree to numerical precision (coefficients are asserted equal in `main.py` and in the tests), so the from-scratch implementation is correct.
- Plain OLS barely beats predicting the mean: with ~47 features and ~200 training rows it overfits. Ridge regularisation is what actually helps. The penalty is chosen by cross-validation on the training split only.
- Fit times are medians over 200 runs; the NumPy solve is faster than scikit-learn on a problem this small, which says nothing about large data.
- Results differ from the original README (R² 0.28) and notebook output (R² 0.21) because of the fixes listed below. Those earlier numbers included a row-index column as a feature and arbitrary label encoding.

## What was fixed

| Problem in the original | Fix |
|---|---|
| The unnamed CSV row-index column was used as a feature | Dropped |
| `2.Gender` was never renamed (no space after the dot) | Explicit rename map; unexpected columns raise an error |
| `">= 90%"` and `">=90%"` were treated as different categories | Whitespace normalised |
| `LabelEncoder` on every column (arbitrary order, and missing values became the string `"nan"`) | Binary → 0/1, ordered answers → ordered integers, unordered → one-hot, multi-select answers → one indicator per choice |
| Missing "community activity" (not in a community) and empty multi-select answers were silently encoded | Handled explicitly as "not in a community" / no choice ticked |
| Target codes `3-Feb` / `5-Apr` (Excel turned "2-3" / "4-5" into dates) | Both spellings accepted, unknown values raise |
| `np.linalg.inv` fails on collinear features | `np.linalg.solve` with pseudo-inverse fallback |
| Colab-only `files.upload()` and `exit()` in a notebook | Plain local file load; logic moved to an importable module |
| Single 52-row test split, no baseline | Mean baseline, 5-fold CV, ridge with penalty chosen on training data only |
| Single `time.time()` fit timing | Median of 200 runs with `perf_counter` |
| Plots mixed MSE and R² on one axis; scatter overplotted a 4-level target | Separate axes, jittered scatter |
| README numbers did not match the notebook | All numbers regenerated by `main.py` |
| No tests, no requirements file | `tests/` and `requirements.txt` added |

## Methodology

1. **Load and clean**: rename columns, normalise whitespace, drop the index column.
2. **Target**: map answers to numbers (None 0, 1 → 1, 2–3 → 2.5, 4–5 → 4.5, More than 5 → 6).
3. **Features**: binary, ordinal, one-hot (levels with under 5 rows pooled into "Other") and multi-hot encoding.
4. **Split** 80/20 with `random_state=42`.
5. **Models**: mean baseline, scikit-learn OLS, manual OLS, manual Ridge.
6. **Evaluate** with MSE, RMSE, MAE, R², and 5-fold CV R².

The manual model solves `θ = (XᵀX + αI)⁻¹ Xᵀ y` (intercept unpenalised; `α = 0` is plain OLS).

## Dataset

Survey responses from 256 students, grouped roughly as:

- **Personal and demographic:** gender, year of study, branch, first-generation graduate status
- **Academic history:** schooling type, percentage, and school location for Class 10 and Class 12; gap year
- **Technical skills and engagement:** active technologies, DSA exposure, GitHub exposure, developer communities, hackathons, software and hardware projects, idea pitching
- **Extracurricular:** volunteer groups, additional skills, achievements

## Limitations

- **Small, noisy data.** 256 rows, and a target with only four levels (only 6 students in the top level), so test metrics move a lot between splits. Trust the CV figures more than the single split.
- **The target is binned.** Survey ranges were converted to midpoints, so this is really an ordinal problem treated as regression.
- **Modest fit.** Even the best model explains roughly a quarter of the variance in cross-validation.
- **Coefficients are not causal.** Several large ones (e.g. `school_type_10_Other`, 4 students) rest on very few rows. Features are unscaled, so ridge shrinks them unevenly.

## Possible Improvements

- Scale features before ridge, try Lasso or tree-based models
- Treat the target as ordinal classification
- Collect more data, especially for the higher language counts
